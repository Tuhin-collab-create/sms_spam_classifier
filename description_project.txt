This notebook outlines a comprehensive machine learning pipeline for classifying SMS messages as "spam" or "ham" (legitimate). The workflow follows a standard data science approach, progressing from raw data ingestion to model deployment.

1. Data Cleaning and Preparation
The process begins with loading the dataset and performing initial cleanup to ensure a high-quality input for the model:

Column Removal: Three unnecessary columns (Unnamed: 2, Unnamed: 3, and Unnamed: 4) containing mostly null values are dropped.

Renaming: Columns are renamed to target (the label) and text (the message content) for better readability.

Label Encoding: The target labels 'ham' and 'spam' are converted into numerical values (0 and 1) using LabelEncoder.

Deduplication: Duplicate entries are identified and removed to prevent the model from learning from redundant data.

2. Exploratory Data Analysis (EDA)
EDA is performed to understand the characteristics of the data:

Class Distribution: The balance between ham and spam messages is visualized using pie charts and count plots.

Text Metrics: New features are created to track the number of characters, words, and sentences in each message using the NLTK library.

Statistical Analysis: Descriptive statistics and heatmaps are used to find correlations between message length and the classification.

3. Text Preprocessing
Raw text is transformed into a clean format through several steps defined in a custom function:

Standardization: Converting all text to lowercase.

Tokenization: Breaking sentences into individual word tokens.

Filtering: Removing special characters, punctuation, and common English "stopwords" (like "is," "the," "and") that do not add significant predictive value.

Stemming: Reducing words to their root form (e.g., "loving" becomes "love") using the Porter Stemmer algorithm.

Visualization: WordClouds are generated to highlight the most frequent terms found in both spam and ham messages.

4. Model Building and Evaluation
The notebook compares multiple machine learning algorithms to find the most accurate and precise predictor:

Vectorization: The processed text is converted into numerical vectors using TfidfVectorizer (Term Frequency-Inverse Document Frequency).

Initial Testing: Three variants of Naive Bayes (Gaussian, Multinomial, and Bernoulli) are tested. Multinomial Naive Bayes (MNB) is identified as a strong candidate due to its high precision.

Algorithm Comparison: Several other classifiers are evaluated, including Logistic Regression, Support Vector Machines (SVM), Decision Trees, Random Forest, AdaBoost, and XGBoost.

Performance Focus: Precision is prioritized over accuracy to minimize "false positives" (marking a legitimate message as spam).

5. Final Export
Once the model is finalized, the necessary components are saved for use in a real-world application:

Model Saving: The trained Multinomial Naive Bayes model and the TF-IDF vectorizer are exported as .pkl files using the pickle library.
